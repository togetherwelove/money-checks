# 금액 화면 평면형 레이아웃 정책

## 상태

- 정책 결정일: 2026-07-23
- 상태: 확정

## 목적

가계부 금액을 확인하거나 입력하는 핵심 화면에서 미색 배경과 카드가 반복되는 단계감을
제거한다. 흰 배경 위에 여백과 얇은 구분선을 사용해 정보를 단순하고 빠르게 읽을 수
있도록 한다.

## 적용 범위

- 홈
- 전체 내역
- 통계
- 내역 등록 및 수정

인증, 계정, 앱 설정, 구독, 후원 화면은 `app-flat-ui-color-policy.md`에 따라 같은
평면화 원칙을 적용한다.

## 공통 원칙

- 핵심 금액 화면의 콘텐츠 배경은 순백색을 사용한다.
- 구조를 만들기 위한 외곽 카드의 배경색, 테두리, 둥근 모서리는 제거한다.
- 화면 너비를 크게 차지하는 구조적 컨테이너에는 둥근 모서리를 사용하지 않는다.
- 버튼, 필터 칩, 날짜 셀처럼 상태와 조작 대상을 직접 표현하는 작은 요소의 둥근
  모서리는 유지한다.
- 섹션 구분은 여백과 얇은 구분선을 우선 사용한다.
- 화면을 가로지르는 섹션 구분선은 좌우 여백 없이 전체 너비로 표시한다.
- 구분선 컨테이너 안의 텍스트, 금액, 목록 등 콘텐츠는 기존 화면 좌우 패딩을 유지한다.
- 카드 제거 후에도 기존 정보 순서와 기능은 변경하지 않는다.
- 공통 헤더와 푸터의 기존 디자인은 유지한다.
- 광고 배경과 구분선은 콘텐츠 좌우 패딩에 제한되지 않고 화면 전체 너비까지
  이어지게 한다.
- 배너 및 네이티브 광고 영역의 배경은 순백색으로 통일한다.
- 광고 소재 자체의 크기와 가운데 정렬은 광고 SDK의 기존 동작을 유지한다.

## 화면별 정책

### 홈

- 달력, 월간 요약, 선택 날짜 내역을 같은 흰 배경 위에 배치한다.
- 화면 콘텐츠는 광고, 월간 요약, 요일과 달력, 선택 날짜 내역 순서로 배치한다.
- 월간 요약의 별도 배경은 제거하고 위아래 구분선은 유지한다.
- 월간 요약의 수입, 지출과 계산 결과 금액은 동일한 글자 크기와 굵기를 사용한다.
- 월간 요약의 위아래 구분선, 요일 헤더 하단선과 달력·내역 목록 사이 구분선은 화면
  전체 너비로 표시한다.
- 달력의 주를 나누는 가로선도 화면 전체 너비로 표시하며 날짜 셀 콘텐츠는 기존 좌우
  정렬을 유지한다.
- 선택 날짜는 달력에서 확인하며 내역 목록 위에 별도 날짜 헤더를 표시하지 않는다.
- 선택 날짜 내역의 각 행 하단선은 전체 너비로 표시하되 행 콘텐츠는 기존 좌우 패딩을
  유지한다.
- 선택 날짜 내역의 금액은 제목과 메타 정보를 포함한 행 전체 높이를 기준으로 수직
  가운데 정렬한다.
- 광고 영역의 시각적 구분은 유지한다.
- pull-to-refresh는 선택 날짜 내역 목록에만 적용하되, 내역이 적거나 없어도 목록의
  남은 빈 공간에서 시작할 수 있어야 한다.

### 전체 내역

- 화면과 내역 행 배경을 흰색으로 통일한다.
- 내역 행은 화면 전체 너비의 하단 구분선으로만 나누고 행 콘텐츠는 기존 좌우 패딩을
  유지한다.
- 내역 금액은 제목과 메타 정보를 포함한 행 전체 높이를 기준으로 수직 가운데 정렬한다.
- 필터 칩은 선택 상태를 전달하는 상호작용 요소이므로 유지한다.
- 전체 내역 리스트는 화면 전체 너비를 사용하고, 일반 내역 행에만 콘텐츠 좌우
  패딩을 적용해 네이티브 광고가 잘리지 않게 한다.
- 네이티브 광고의 배경은 전체 너비를 유지한다.
- 네이티브 광고의 아이콘, 문구와 하단 구분선은 일반 내역과 같은 좌우 패딩으로
  정렬한다.

### 통계

- 도넛 차트와 막대 차트의 외곽 카드 배경, 테두리, 둥근 모서리를 제거한다.
- 배너 광고는 월별 추이와 원그래프보다 앞선 차트 화면 최상단에 배치한다.
- 통계 페이지 컨테이너는 화면 전체 너비를 사용하고 제목, 차트, 범례 등 실제 콘텐츠에만
  화면 좌우 패딩을 적용한다.
- 통계 섹션은 여백과 화면 전체 너비의 구분선으로 나눈다.
- 분할 선택기의 하단 기준선은 화면 전체 너비로 표시하되 선택 항목과 텍스트는 기존
  좌우 패딩 안에 정렬한다.
- 카테고리별 및 구성원별 분할 선택기는 적용 대상 그래프 바로 앞에 배치한다.
- 사용자는 선택한 뒤 변경된 그래프 제목과 데이터를 순서대로 확인한다.
- 원그래프 아래의 별도 항목 활성화 영역은 제거한다.
- 원그래프 우측 목록에는 활성 및 비활성 항목을 모두 표시하고, 각 행을 눌러 그래프
  포함 여부를 전환한다.
- 우측 목록은 기존 원그래프 높이 안에서 스크롤되며, 모든 항목을 제외한 상태에서도
  다시 항목을 활성화할 수 있어야 한다.
- 우측 목록의 마지막에는 다음 항목이 약 절반 노출되도록 행 높이를 조정해 스크롤
  가능한 영역임을 시각적으로 전달한다.
- 차트, 범례, 선택 상태, 수입 및 지출 강조색은 유지한다.

### 내역 등록 및 수정

- 신규 등록과 기존 내역 수정은 iOS 네이티브 스택의 `formSheet` 화면으로 통일한다.
- 푸터 가운데 등록 버튼은 클립보드 선택 흐름이 끝난 뒤 네이티브 시트 라우트로
  이동한다.
- 시트 표시는 네이티브 내비게이션 라우트 상태로만 관리한다. 별도의 `isOpen`,
  `present`, `dismiss` 또는 animation frame 상태를 두지 않는다.
- 시트는 화면 높이의 92% 단일 detent로 열고 시스템 grabber를 표시한다.
- 바텀 시트는 폼을 충분히 표시할 수 있는 최대 높이로 열고, 내용이 넘치거나 키보드가
  표시되면 시트 내부에서 스크롤한다.
- 바텀 시트에는 별도 헤더와 닫기 버튼을 표시하지 않는다.
- 시스템 아래 스와이프로만 닫기를 요청한다. 네이티브 시트에서 보장되지 않는 배경
  탭 닫기는 제공하지 않는다.
- 초안이 처음 열린 상태와 다르면 네이티브 화면 제거를 막고 폐기 확인을 거친 후
  닫는다. 변경 사항이 없으면 즉시 닫는다.
- 저장이 완료되면 바텀 시트를 닫고 진입 전 화면을 그대로 유지한다.
- 바텀 시트 안에는 Free 배너 광고를 표시하지 않는다.
- 등록 및 수정 버튼은 고정하지 않고 입력 폼의 마지막 동작으로 배치한다.
- 바텀 시트의 하단에는 공통 푸터 높이나 키보드용 추가 공간을 두지 않고 기기 안전
  영역만 적용한다.
- 바텀 시트에는 네이티브 스택이 인식할 수 있는 일반 `ScrollView` 하나와 React
  Native `TextInput`을 사용한다. Gorhom 전용 컴포넌트와 키보드 처리는 사용하지 않는다.
- `ScrollView`의 iOS 키보드 인셋 자동 조정을 활성화해 포커스된 입력란이 키보드에
  가려지지 않게 한다.
- 입력 포커스 좌표 측정, 강제 `scrollTo`, 입력 높이를 이용한 추가 스크롤을 구현하지
  않고 iOS 네이티브 시트와 스크롤의 키보드 처리에 맡긴다.
- 시트가 표시될 때는 입력란을 자동 포커스하지 않는다. 사용자가 분류를 선택하면
  금액란이 비어 있을 때는 금액란으로, 값이 있을 때는 내용란으로 포커스를 이동한다.
- 입력 폼 전체를 감싸는 외곽 카드를 제거한다.
- 등록 및 수정 시트의 최상단에는 전체 폭 날짜 선택 행을 배치하고, 그 아래에 지출 및
  수입 선택기를 배치한다. 날짜 행을 누르면 iOS 인라인 달력 모달을 연다.
- 날짜 변경은 신규 등록과 수정 모두 현재 초안의 `date`에만 적용한다. 작성 중인 다른
  값과 진입 전 화면의 날짜 선택 상태는 유지한다.
- 금액, 내용, 메모 입력란은 배경색, 외곽선, 둥근 모서리를 제거하고 밑줄로 입력
  영역을 표시한다.
- 내용과 메모는 동일한 제목 행, 간격과 한 줄 입력 높이를 사용한다.
- 신규 등록의 결제 방식 선택은 분류와 내용 사이의 전체 폭 선택 행으로 분리하고,
  왼쪽에 `결제 방식`, 오른쪽에 현재 선택값과 아래 방향 아이콘을 표시한다.
- 지출 및 수입 선택기는 외곽 배경과 테두리 없이 하단 기준선과 선택 항목의 상태색
  밑줄로 표시한다.
- 지출 및 수입 선택기는 입력 본문의 금액 입력란 바로 위에 배치하고, `금액` 라벨을
  대신하는 제목형 선택기로 사용한다.
- 지출 및 수입 선택기는 시트의 콘텐츠 좌우 폭을 모두 사용하고 두 항목을 같은 너비로
  배치한다. 시트 상단 경계와 선택기 사이에는 공통 카드 내부 여백을 둔다.
- 분류 선택 그리드는 휴대폰 화면 한 줄에 최소 6개 항목이 배치되도록 셀 크기를
  반응형으로 계산한다.
- 입력 항목 사이는 기존 여백 구조를 유지한다.

## 유지 대상

- 버튼, 필터, 모달, 광고
- 달력 선택 상태와 히트맵
- 수입 및 지출 상태색
- 로딩, 오류, 빈 상태
